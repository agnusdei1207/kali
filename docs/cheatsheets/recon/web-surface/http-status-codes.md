# HTTP 상태 코드 치트시트 (침투 테스트 관점)

> 퍼징/스캔 결과를 해석할 때 마주치는 상태 코드 정리.
> 핵심: 상태 코드 = 서버가 준 힌트. 무조건 버리지 말고 의미를 읽는다.

---

## 1. 코드 구조 (5개 클래스)

| 클래스 | 의미 | 예시 |
|:---:|---|---|
| `1xx` | 정보 (처리 중) | 100, 101 |
| `2xx` | 성공 | 200, 201, 204 |
| `3xx` | 리다이렉트 | 301, 302, 307 |
| `4xx` | 클라이언트 오류 | 400, 401, 403, 404 |
| `5xx` | 서버 오류 | 500, 502, 503 |

---

## 2. 자주 보는 코드 상세

### 2xx — 성공

| 코드 | 이름 | 의미 | 펜테스트 힌트 |
|:---:|---|---|---|
| 200 | OK | 정상 응답, 본문 있음 | 페이지 존재, 접근 가능 |
| 201 | Created | 생성 성공 (POST 결과) | API 엔드포인트 존재 |
| 204 | No Content | 성공, 본문 없음 | 빈 응답 API, 삭제 요청 성공 |
| 206 | Partial Content | 부분 응답 (Range 요청) | 파일 다운로드/스트리밍 기능 |

### 3xx — 리다이렉트 ⭐ (퍼징에서 가장 중요)

| 코드 | 이름 | 의미 | 펜테스트 힌트 |
|:---:|---|---|---|
| 301 | Moved Permanently | 영구 이동 | 구조 파악 (예: http→https 강제) |
| 302 | Found (임시 이동) | 임시 리다이렉트 | 인증 게이트 신호 — 페이지는 존재하는데 로그인 안 돼서 login.php로 튕김 |
| 303 | See Other | GET으로 다른 곳 조회 | 폼 처리 후 이동 |
| 307 | Temporary Redirect | 임시 이동, 메서드 유지 | POST 데이터 유지하며 이동 |
| 308 | Permanent Redirect | 영구 이동, 메서드 유지 | 301의 메서드 유지 버전 |

> 💡 302 해석법
> - 로그인 페이지인데 302 → 이미 로그인된 세션 (리다이렉트 목적지 확인)
> - 보호 페이지인데 302 → `Location: login.php` = "존재하지만 권한 없음"
> - 즉 302는 페이지 존재의 증거. 무조건 필터링하면 놓친다.

### 4xx — 클라이언트 오류 ⭐

| 코드 | 이름 | 의미 | 펜테스트 힌트 |
|:---:|---|---|---|
| 400 | Bad Request | 잘못된 요청 형식 | 파라미터 검증이 있다는 신호 |
| 401 | Unauthorized | 인증 안 됨 (누구인지 모름) | 유효 자격증명 필요 — 브루트포스 후보 |
| 403 | Forbidden | 권한 없음 (누구인지는 알지만 거절) | 페이지 존재 가능성 높음 — 우회 시도 대상 |
| 404 | Not Found | 존재하지 않음 | 퍼징 시 기본 제외 대상 |
| 405 | Method Not Allowed | 허용 안 되는 HTTP 메서드 | "GET은 안 되고 POST는 된다" 가능성 |
| 429 | Too Many Requests | 요청 과다 (Rate limit) | 스레드 줄이거나 지연 추가 필요 |

> 💡 401 vs 403 차이 (시험에도 자주 나옴)
> - `401` = "너 누군지 모르겠다. 로그인해라"
> - `403` = "너 누군지는 아는데 접근 권한이 없다"
> - 403이 뜨면 페이지는 존재하므로 경로 변조, 헤더 조작(XFF 등) 우회 시도 가치 있음

### 5xx — 서버 오류

| 코드 | 이름 | 의미 | 펜테스트 힌트 |
|:---:|---|---|---|
| 500 | Internal Server Error | 서버 내부 오류 | 취약점 신호! 애플리케이션 크래시 → 입력값 검증 허점 가능성 |
| 502 | Bad Gateway | 업스트림 서버 문제 | 리버스 프록시 구조 존재 |
| 503 | Service Unavailable | 서비스 불가/과부하 | 잠시 대기, 또는 WAF 차단 가능성 |

## 3. 퍼징 시 필터링 전략

### ffuf / wfuzz / gobuster 옵션 대응

| 동작 | ffuf | wfuzz | gobuster |
|---|---|---|---|
| 상태 코드 보이기 | `-mc 200,301` | `--sc 200,301` | `-s 200,301` |
| 상태 코드 숨기기 | `-fc 404` | `--hc 404` | `-b 404` |
| 라인 수 숨기기 | `-fl 12` | `--hl 12` | — |
| 크기 숨기기 | `-fs 178` | `--hs 178` | — |
| 단어 수 숨기기 | `-fw 5` | `--hw 5` | — |

### 실전 팁

```bash
# 나쁜 예: 302까지 버리면 보호 페이지를 놓침
ffuf -u http://target/FUZZ -w wordlist.txt -fc 404,302

# 좋은 예: 404만 제외하고 302/403은 남겨서 해석
ffuf -u http://target/FUZZ -w wordlist.txt -fc 404
```

상태 코드별 해석 우선순위 (디렉토리 퍼징 시):

| 응답 | 해석 |
|---|---|
| 200 | 존재 + 열람 가능 → 바로 확인 |
| 301/302 | 존재 + 리다이렉트 → `Location` 목적지 확인 (인증 게이트?) |
| 401 | 존재 + 인증 필요 → 크리덴셜/브루트포스 후보 |
| 403 | 존재 가능성 높음 → 헤더/경로 우회 시도 |
| 500 | 예상치 못한 크래시 → 페이로드별로 기록, 취약점 조사 |
| 404 | 없음 → 제외 (단, 커스텀 404는 200을 돌려주므로 크기 필터 필요) |

> ⚠️ 소프트 404 주의: 존재하지 않는 경로인데 200 + "Not Found" 본문을 주는 서버도 있음.
> → 아무 단어나 넣고 기본 응답 크기(`-fs`)를 재서 필터링.

## 4. 빠른 참조 카드

```
200 OK        성공
301 영구 이동  SEO용, 구조 파악
302 임시 이동  ★ 인증 게이트 (Location 확인)
400 형식 오류  파라미터 검증 존재
401 인증 필요  ★ 브루트포스 후보
403 권한 없음  ★ 우회 시도 대상
404 없음      기본 제외
405 메서드 금지  POST로 재시도
429 과다 요청  지연/스레드 조절
500 서버 오류  ★ 취약점 신호
503 서비스 불가  WAF/과부하 가능성
```
