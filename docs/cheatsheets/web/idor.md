# idor (Insecure Direct Object Reference)

## 개요

IDOR(취약한 직접 객체 참조)는 사용자가 입력한 식별자(ID)를 그대로 받아, 타인의 데이터에 접근할 수 있게 하는 취약점이다. OSCP 웹 공격 단계에서 빈출이다.

## 확인할 형태

| 형태 | 예시 |
|------|------|
| URL 파라미터 | `?id=1001` → `?id=1002` |
| 헤더/쿠키 | `X-User-ID: 1001` |
| POST 바디 | `user_id=1001` |

## 사용법

```bash
# 본인 프로필 조회
curl "http://target/profile?id=1001"

# 다른 사용자 프로필 시도 (IDOR)
curl "http://target/profile?id=1002"
```

- `id=1001`로 본인 정보가 보인다면, `1002` 등으로 순회해 다른 사용자 정보가 보이는지 확인한다.
- 결과에 다른 사용자의 이름·이메일·주문 내역이 보이면 IDOR 확인.

## 실전 흐름

1. 본인 계정으로 로그인해 프로필 URL을 확인한다.
2. ID 값을 1씩 바꾸며 다른 사용자 데이터에 접근 가능한지 테스트한다.
3. 발견되면, 수정/삭제 요청(PUT/DELETE)까지 시도해 권리 변경 여부를 확인한다.

## 방어

- 서버에서 요청한 ID가 세션 사용자의 소유인지 확인한다(권한 검사).
- 예측 불가능한 식별자(UUID 등)를 사용한다.
