원인: 오류를 "입력 부족"으로 오판

잘못된 block switch 가 들어옴
        │
디코더가 영구 포맷 오류가 아니라 "입력이 더 필요함" 으로 보고
        │
스트리밍 디코더가 계속 입력을 받아 8바이트 내부 버퍼에 덧붙임
        │
버퍼 경계를 넘어 쓰기 (out-of-bounds write)
        │
프로세스 메모리 손상 → 크래시 / 메모리 노출 / 코드 실행

핵심은 "복구 불가능한 오류" 와 "데이터가 더 오면 해결될 상태" 를 구분하지 못한 상태 처리입니다.

왜 위험한가

공격자가 하는 일

  • 조작된 Brotli 스트림을 서비스가 해제하도록 전달
  • 인증이나 특별한 권한이 필요한 구조가 아님 (해제 지점이 외부에 열려 있으면)

점검할 노출 지점 (예시)

  • 사용자 업로드 파일 해제
  • 외부 서버 응답을 받아 해제하는 클라이언트, 프록시
  • 요청 본문이나 메시지를 Brotli 로 받는 API

node:zlib 의 Brotli API 를 직접 쓰지 않아도, 의존 라이브러리가 내부에서 쓸 수 있습니다.

대응

즉시

  • 22.23.4 / 24.22.1 / 26.12.1 이상으로 업그레이드 (더 최신 패치가 있는지 확인)
  • 컨테이너 베이스 이미지 재빌드, 재배포
  • EOL 버전 (20 이하) 은 패치가 없으므로 지원 버전으로 이전

점검

  • 코드와 의존성에서 zlib.brotliDecompress, createBrotliDecompress 사용처 검색
  • 외부 입력이 해제 단계로 들어가는 경로 파악
  • 해제 크기, 입력 크기 제한과 프로세스 격리 확인

같은 릴리스의 나머지

High 는 Brotli 한 건만 다루고, 나머지는 공식 공지에서 확인합니다.

  • Medium: HTTP keep-alive 소켓 응답 오인, 스냅샷/SEA 에서 난수 반복, TLS 비정규 IPv4 검증
  • Low: ZipFile 불일치, Permission Model 우회 2건
