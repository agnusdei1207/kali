# 인사이트 문서 작성법 가이드

기술 연구나 보안 분석 결과를 효과적으로 전달하는 문서 작성 가이드입니다.

## 📋 기본 구조

```
# 제목: [기술/취약점 이름]

## 핵심 요약
한 문단(3-4줄)으로 문제의 본질 설명

## 배경
- 왜 이걸 연구했나?
- 어떤 문제에서 시작했나?

## 연구 과정

### 1단계: 초기 접근
- 시도한 방법
- 예상한 결과

### 2단계: 첫 번째 장벽
- **문제**: 구체적으로 무엇이 안 됐는가?
- **이유**: 왜 작동하지 않았는가?
- **해결**: 어떻게 우회했는가?

### 3단계: 다음 장벽
(필요한 만큼 반복)

## 최종 솔루션
최종적으로 작동하는 방식의 명확한 설명

## 핵심 인사이트
- **인사이트 1**: 배운 점과 그 의미
- **인사이트 2**: 일반화할 수 있는 패턴
- **인사이트 3**: 미래에 적용할 수 있는 원칙

## 실제 예시
코드, 페이로드, 또는 명령어

## 검증 방법
어떻게 이게 작동하는지 확인했는가?
```

## ✍️ 작성 원칙

### 1. 노이즈 제거
- ❌ 불필요한 기술 용어 설명 제외
- ❌ 시도했지만 관련 없는 내용 제외
- ✅ 최종 성공까지의 **주요 전환점**만 포함

### 2. 인과관계 명확히
```
시도 → 문제 발생 → 원인 파악 → 해결책 → 결과
```

각 단계가 다음 단계로 자연스럽게 연결되도록 작성

### 3. 독자 입장 고려
- 배경 지식이 없어도 이해 가능하게
- 왜 이 방식을 선택했는지 설명
- 다른 방법은 왜 안 되는지 언급

### 4. 구체성
- ❌ "여러 문제가 있었다"
- ✅ "htmLawed 필터와 커스텀 정제 함수 두 계층을 우회해야 했다"

### 5. 인사이트는 일반화
- ❌ "이 취약점에만 해당하는 얘기"
- ✅ "보안 레이어는 단일 우회가 아닌 각 계층별 다른 전략이 필요하다"

## 📊 체크리스트

문서 완성 전 확인사항:

- [ ] 핵심 요약이 한 문단인가?
- [ ] 각 장벽마다 "문제 → 이유 → 해결" 구조가 있는가?
- [ ] 최종 솔루션이 명확하게 설명되어 있는가?
- [ ] 인사이트가 3개 이상 있는가?
- [ ] 인사이트가 이 주제에만 국한되지 않고 일반화되어 있는가?
- [ ] 코드/예시가 구체적인가?
- [ ] 기술 전문가가 아닌 사람도 이해할 수 있는가?
- [ ] 불필요한 설명이 있는가?

## 🎯 나쁜 예 vs 좋은 예

### ❌ 나쁜 예
```
많은 시도를 했고 여러 문제가 있었습니다. 결국 작동하는 방식을 찾았습니다.
PHP 필터를 사용했습니다. 코드는 여기있습니다.
```

### ✅ 좋은 예
```
**문제**: htmLawed 필터가 인코딩된 콜론 %3a를 차단했습니다.
**이유**: 화이트리스트 기반 검증이 모든 변형을 포함했기 때문입니다.
**해결**: URL 키워드와 괄호 사이에 공백을 삽입하니 필터를 우회할 수 있었습니다.
**배운 점**: 정제 함수는 패턴만 보지만, 공백 같은 시각적 요소는 놓칩니다.
```
