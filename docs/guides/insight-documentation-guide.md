# 인사이트 문서 작성법

취약점 분석이나 기술 연구 결과를 효과적으로 정리하는 가이드입니다.

## 기본 구조

```
# 제목

한 문단 요약

## 문제
무엇이 되고 왜 생겼는가

## 해결 과정

### 1. 첫 시도 (실패)
- 뭘 했나
- 왜 실패했나

### 2. 두 번째 시도
- 문제가 뭐였나
- 어떻게 우회했나

### 3. 최종 성공
- 결과

## 배운 점
- 인사이트 1 (일반화된)
- 인사이트 2 (다른 곳에 적용 가능)

## 실제 코드/예시

## 검증 방법
```

## 작성 원칙

### 1. 핵심만
- 성공까지의 주요 전환점만 포함
- 막힌 부분, 삭제한 부분은 제외
- 불필요한 설명 최소화

### 2. 명확한 흐름
시도 → 문제 → 원인 → 해결 → 배운 점

### 3. 배운 점은 일반화
- 이 취약점만 해당하는 게 아니라
- 다른 보안 문제에도 적용 가능한 원칙

### 4. 독자 입장
- 배경 지식 없어도 이해 가능
- 왜 이 방법을 선택했는지 명확

## 체크리스트

- [ ] 핵심 요약이 한 문단인가
- [ ] 각 단계가 문제 → 원인 → 해결 구조인가
- [ ] 배운 점이 3개 이상이고 일반화되었는가
- [ ] 코드/예시가 구체적인가
- [ ] 비전문가도 이해할 수 있는가
- [ ] 불필요한 부분이 없는가
