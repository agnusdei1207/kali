# 롸잇업 작성법

독자가 무엇을 보고, 왜 다음 행동을 했는지 따라갈 수 있게 쓴다. 과정은 시간순으로 적고, 판단에 필요한 내용만 남긴다.

## 작성 원칙

- 한 단계에는 `관찰 → 판단 → 실행 → 결과`를 짧게 담는다. 같은 사실을 여러 절에서 반복하지 않는다.
- 각 단계는 한 문장으로 요약하고, 설명은 최대 3문장으로 제한한다. 길어지면 핵심만 1~3개 불렛으로 적는다.
- 실제 실행한 명령과 결과만 성공 기록으로 쓴다. 명령이 기억나지 않으면 `재현 예시`라고 한 번만 표시한다.
- 출력은 판단에 필요한 한두 줄만 인용한다. 실패도 다음 선택에 영향을 줬다면 짧게 적는다.
- 명령 뒤에 옵션 뜻을 줄줄이 나열하지 않는다. 판단에 꼭 필요한 옵션만 설명한다.
- 확인한 사실과 추정을 구분하되, 미완료 상태나 주의 문구를 단계마다 반복하지 않는다.
- 본문에서 굵은 글씨를 쓰지 않는다. 제목, 목록, 코드 표기로 구분한다.
- 한국어로 간결하게 쓰고, `사용자의 기억에 따르면` 같은 작성 경위는 본문에 넣지 않는다.
- 플래그·비밀번호·개인키·토큰은 본문, 출력, 이미지에서 가린다.

## 구성

1. 문제 정보: 대상, 취약점, 목표를 짧게 적는다.
2. 현재 상태: 진행 중이면 확인한 지점과 막힌 지점을 한두 문장으로 적는다.
3. 사고 흐름: 실제로 진행한 순서를 번호로 요약한다.
4. 풀이 과정: 단계마다 관찰, 명령, 핵심 결과, 다음 행동을 적는다. 정상 동작을 먼저 확인한다.
5. 근본 원인: 입력이 어디로 전달돼 문제가 생겼는지 설명한다.
6. 핵심 교훈: 다른 문제에도 적용할 판단 기준을 남긴다.
7. 최종 재현 명령과 결과: 검증한 경우에만 적고, 미완료면 그대로 표시한다.

예를 들어 경로 탐색 단계는 다음 정도면 충분하다.

```markdown
### 경로 탐색

`ffuf`로 `/osticket/`을 찾았다. 브라우저에서 Support Center가 열려 조사 대상을 osTicket으로 좁혔다.

재현 예시(원래 명령 기록 미확인):

~~~bash
ffuf -u 'http://TARGET/FUZZ' -w /usr/share/seclists/Discovery/Web-Content/raft-large-directories.txt -fc 404
~~~

`-w`는 경로 후보 목록을 지정하고, `-fc 404`는 404 응답을 숨긴다.
```

## 이미지 첨부

스크린샷은 화면의 상태를 보여 줄 때만 쓴다. 명령과 핵심 출력은 본문에도 복사 가능한 텍스트로 적는다. 이미지에 이메일 주소, 계정, 플래그, 키가 보이지 않는지 업로드 전에 확인한다.

저장소 안에서만 볼 문서는 이미지 파일을 함께 두고 상대 경로로 연결한다. 최상단의 롸잇업이라면:

```markdown
![티켓 생성 성공 화면](./figures/cve-2026-22200-ticket-created-v1.png)
```

다른 사이트에도 문서를 게시할 때는 `agnusdei1207/public`의 문서별 GitHub Release에 이미지를 올리고 공개 URL을 넣는다. 이미지 파일을 `figures/`에 준비했다면:

```bash
gh auth login
gh release create cve-2026-22200-assets-v1 \
  figures/cve-2026-22200-ticket-created-v1.png \
  --repo agnusdei1207/public \
  --title 'CVE-2026-22200 이미지 v1' \
  --notes '롸잇업 공개 이미지' \
  --latest=false
```

같은 릴리스에 이미지를 추가할 때는 `gh release upload <태그> <파일> --repo agnusdei1207/public`을 사용한다. 수정본은 파일명에 새 버전을 붙인다. 문서에는 다음처럼 링크하고 로그아웃 상태에서도 열리는지 확인한다. [릴리스 생성](https://cli.github.com/manual/gh_release_create) · [파일 추가](https://cli.github.com/manual/gh_release_upload)

```markdown
![티켓 생성 성공 화면](https://github.com/agnusdei1207/public/releases/download/cve-2026-22200-assets-v1/cve-2026-22200-ticket-created-v1.png)
```

## 최종 결과

플래그를 얻고 제출까지 확인했다면 결과만 `REDACTED`로 적는다. 실제 값의 일부도 공개하지 않는다. 아직 얻지 못했으면 `미획득`으로 적는다.

```markdown
## 최종 결과

검증 완료. 플래그: `REDACTED`
```

## 완료 전 확인

- [ ] 관찰과 결과가 다음 행동으로 이어지는가?
- [ ] 명령과 주요 옵션을 재현할 수 있는가?
- [ ] 추정이나 재현 예시를 실제 실행 결과처럼 쓰지 않았는가?
- [ ] 같은 설명과 주의 문구를 반복하지 않았는가?
- [ ] 플래그와 민감 정보가 본문·출력·이미지에서 가려졌는가?
- [ ] 이미지 링크가 열리고, 최종 결과가 검증 상태와 일치하는가?
