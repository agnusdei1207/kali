> [!IMPORTANT]
> **롸잇업 작성 규칙:** 모든 신규 롸잇업은 반드시 [롸잇업 작성 가이드](WRITEUP_GUIDE.md)를 따라야 합니다. 사고의 흐름, 판단 근거, 재현 가능한 명령어, 주요 옵션과 페이로드를 사용한 이유, 결과 해석, 근본 원인 및 대응책을 생략하지 않습니다. 체크리스트를 충족하지 않은 문서는 완료본으로 취급하지 않습니다.

# 1. 랩 환경 & 저장소 아키텍처

본 저장소는 Docker 기반의 격리된 Kali Linux 공격 환경과 체계적인 기법 치트시트, 실전 롸잇업을 유기적으로 결합한 침투 테스트 실습 프레임워크입니다.

## 랩 인프라 아키텍처

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        Host OS (Windows / Linux)                       │
│                                                                        │
│   ┌──────────────────────┐             ┌───────────────────────────┐   │
│   │   Docker Compose     │             │   Workspace Files         │   │
│   │   (compose.yml)      │             │   - item/ (CheatSheets)   │   │
│   └──────────┬───────────┘             │   - completed/ (Writeups) │   │
│              │                         └─────────────┬─────────────┘   │
│              ▼                                       │                 │
│   ┌──────────────────────────────────────────────┐   │ (Volume Mount)  │
│   │   Kali Container (kali-rolling)              │   │ /data           │
│   │   - Privileged & Host Network Mode           │◄──┘                 │
│   │   - Net Admin / Raw Packet Capabilities      │                     │
│   │   - Pre-installed Pentest Toolchain          │                     │
│   └──────────────────────┬───────────────────────┘                     │
└──────────────────────────┼─────────────────────────────────────────────┘
                           │ OpenVPN Tunneling (/vpn/vpn.ovpn)
                           ▼
┌────────────────────────────────────────────────────────────────────────┐
│            Target Networks (CTF Platforms / VulnLab / THM)             │
└────────────────────────────────────────────────────────────────────────┘
```

# 2. 침투 테스트 방법론 개요

PTES(Penetration Testing Execution Standard) 및 MITRE ATT&CK 프레임워크를 기반으로 수립된 9단계 침투 테스트 공격 라이프사이클입니다.

## 전체 프로세스 아키텍처

```
┌─────────────────────────────────────────────────────────────────┐
│                    침투 테스트 라이프사이클                         │
├─────────────────────────────────────────────────────────────────┤
│  1. 정보 수집      →  2. 취약점 분석  →  3. 초기 침투           │
│     (Reconnaissance)   (Vulnerability     (Initial Access)       │
│                        Assessment)                               │
├─────────────────────────────────────────────────────────────────┤
│  4. 권한 상승      →  5. 권한 유지    →  6. 측면 이동           │
│     (Privilege        (Persistence)      (Lateral Movement)      │
│     Escalation)                                                  │
├─────────────────────────────────────────────────────────────────┤
│  7. 증거 수집      →  8. 정리 및 복구 →  9. 보고서 작성         │
│     (Evidence         (Cleanup)          (Reporting)             │
│     Collection)                                                  │
└─────────────────────────────────────────────────────────────────┘
```

---

## 단계별 세부 가이드라인

### 1. 정보 수집 (Reconnaissance) 단계

정보 수집은 대상 시스템에 대한 모든 가용 정보를 수집하는 첫 번째 단계로, 수동적 정보 수집과 능동적 정보 수집으로 구분됩니다.

```
정보 수집 계층 구조:
┌─────────────────────────────────────────────┐
│           수동적 정보 수집                     │
│  (OSINT, DNS 조회, 공개 데이터베이스)           │
├─────────────────────────────────────────────┤
│           능동적 정보 수집                     │
│  (포트 스캐닝, 서비스 열거, 배너 그래빙)        │
├─────────────────────────────────────────────┤
│         웹 애플리케이션 매핑                   │
│  (디렉터리 열거, 기술 스택 식별)                │
└─────────────────────────────────────────────┘
```

- **핵심 구성 요소**:
  - **네트워크 스캐닝**: 활성 호스트 및 열린 포트 식별 ([`item/reconnaissance`](item/reconnaissance/))
  - **서비스 열거**: 실행 중인 서비스 및 버전 정보 수집 ([`item/enumeration`](item/enumeration/))
  - **웹 애플리케이션 분석**: 디렉터리 브루트포싱 및 기술 스택 파악

---

### 2. 취약점 분석 (Vulnerability Assessment) 단계

수집된 정보를 바탕으로 잠재적 공격 벡터를 식별하고 취약점을 분류/검증합니다.

```
취약점 분석 프로세스:
┌─────────────────────────────────────────────┐
│            자동화 스캐닝                      │
│   (Nmap Scripts, Nikto, 기본 도구)          │
├─────────────────────────────────────────────┤
│            수동 검증                         │
│   (False Positive 제거, 깊이 있는 분석)       │
├─────────────────────────────────────────────┤
│            익스플로잇 가능성 평가              │
│   (CVE 매칭, PoC 검증, 영향도 분석)          │
└─────────────────────────────────────────────┘
```

- **취약점 카테고리 분류**:
  - **네트워크 서비스 취약점**: SMB, SSH, FTP 등 네트워크 프로토콜 취약점
  - **웹 애플리케이션 취약점**: SQLi, XSS, SSRF, LFI/RFI, 파일 업로드 등 ([`item/SQLi`](item/SQLi/), [`item/ssrf`](item/ssrf/))
  - **시스템 구성 취약점**: 기본 자격증명, 미흡한 접근 제어, 잘못된 권한 설정

---

### 3. 초기 침투 (Initial Access) 단계

식별된 취약점을 트리거하여 타겟 시스템의 초기 셸 또는 실행 권한을 확보합니다. [롸잇업 가이드](WRITEUP_GUIDE.md)에 명시된 **'정상 동작 확인(Baseline) → 가설 수립 → Exploit 검증'**의 엄격한 인과관계를 따릅니다.

```
초기 침투 경로:
┌─────────────────────────────────────────────┐
│              인증 우회                       │
│   (브루트포스, 기본 자격증명, 인증 결함)        │
├─────────────────────────────────────────────┤
│             웹 애플리케이션                   │
│   (SQL 인젝션, 파일 업로드, RCE, 웹쉘)        │
├─────────────────────────────────────────────┤
│             네트워크 서비스                   │
│   (버퍼 오버플로우, 원격 코드 실행 CVE)        │
└─────────────────────────────────────────────┘
```

- **성공적인 침투의 핵심 원칙**:
  - **정확한 타겟팅**: 공격 표면이 가장 넓거나 영향도가 확실한 벡터부터 우선 시도
  - **수동 접근법**: 블랙박스 자동화 공격 도구보다 페이로드의 동작 원리를 이해하고 커스텀 적용
  - **리버스 셸 환경 안정화**: 침투 즉시 인터랙티브 TTY 셸로 업그레이드 ([`item/reverse_shell`](item/reverse_shell/), [`item/shell_upgrade`](item/shell_upgrade/))

---

### 4. 권한 상승 (Privilege Escalation) 단계

획득한 제한된 계정 권한에서 최고 관리자(Root / SYSTEM) 권한으로 상승시키는 단계입니다.

```
권한 상승 방법론:
┌─────────────────────────────────────────────┐
│              수평적 권한 상승                 │
│   (동일 권한 레벨 내 다른 사용자 계정 획득)     │
├─────────────────────────────────────────────┤
│              수직적 권한 상승                 │
│   (일반 사용자 → Root / Administrator 권한)    │
├─────────────────────────────────────────────┤
│              시스템 무결성 장악               │
│   (커널 제어, SAM/Shadow 덤프, 보안 도구 우회) │
└─────────────────────────────────────────────┘
```

- **플랫폼별 접근법 ([`item/privilege-escalation`](item/privilege-escalation/))**:
  - **Linux 환경**: Sudo 설정 악용([`item/sudo.md`](item/sudo.md)), SUID/SGID 바이너리, Crontab 스케줄러([`item/crontab.md`](item/crontab.md)), 커널 익스플로잇
  - **Windows 환경**: 서비스 바이너리 하이재킹, 레지스트리 권한 결함, 토큰 조작(SeImpersonate 등), Active Directory 도메인 권한 상승

---

### 5. 권한 유지 (Persistence) 단계

침투한 시스템에서 재부팅이나 세션 종료 후에도 재접속 권한을 유지하기 위한 백도어 및 지속성 메커니즘을 구성합니다.

```
권한 유지 전략:
┌─────────────────────────────────────────────┐
│              시스템 레벨                      │
│   (서비스 등록, 데몬 생성, 시스템 파일 변조)    │
├─────────────────────────────────────────────┤
│              사용자 레벨                      │
│   (SSH authorized_keys 추가, 프로필 스크립트)  │
├─────────────────────────────────────────────┤
│             애플리케이션 레벨                  │
│   (웹쉘 난독화 설치, DB 트리거 백도어)        │
└─────────────────────────────────────────────┘
```

---

### 6. 측면 이동 (Lateral Movement) 단계

초기 침투 시스템을 발판(Pivot) 삼아 내부망의 다른 세그먼트나 추가 호스트로 침투 범위를 확장합니다.

```
측면 이동 프로세스:
┌─────────────────────────────────────────────┐
│            내부 네트워크 탐색                  │
│   (ARP 캐시, 라우팅 테이블, 인터페이스 확인)    │
├─────────────────────────────────────────────┤
│            자격증명 수집 (Harvesting)         │
│   (메모리 덤프, 브라우저/설정 파일 비밀번호)   │
├─────────────────────────────────────────────┤
│            피보팅 & 원격 실행                 │
│   (SSH 터널링, Chisel, Proxychains 악용)      │
└─────────────────────────────────────────────┘
```

- **핵심 기법**: SSH Local/Remote/Dynamic 포워딩, SOCKS 프록시 연계([`item/proxy`](item/proxy/), [`item/ssh`](item/ssh/))

---

### 7. 증거 수집 (Evidence Collection) 단계

모의 침투 성공 및 취약점 영향도를 입증하기 위해 최소한의 필요 증거(Proof of Concept)를 객관적으로 수집합니다.

```
증거 수집 체계:
┌─────────────────────────────────────────────┐
│            시스템 무결성 식별                 │
│   (whoami, id, hostname, ip a / ifconfig)   │
├─────────────────────────────────────────────┤
│            목표 데이터 (Flags / Artifacts)  │
│   (user.txt, root.txt, 중요 환경변수)        │
├─────────────────────────────────────────────┤
│            영향도 입증 기록                   │
│   (실행 화면 캡처, 타임스탬프, 설정 파일 사본) │
└─────────────────────────────────────────────┘
```

---

### 8. 정리 및 복구 (Cleanup) 단계

테스트 완료 후 타겟 시스템을 최초 상태로 완벽히 원상 복구하여 보안 위협 및 운영 부작용을 방지합니다.

```
정리 및 복구 절차:
┌─────────────────────────────────────────────┐
│  1. 업로드 파일 제거 (/tmp 도구, 웹쉘, 스크립트) │
│  2. 임시 생성 계정 및 변경된 권한 원복         │
│  3. 백도어 및 크론/스케줄 작업 제거            │
│  4. 불필요하게 남긴 테스트 로그 및 세션 정리   │
└─────────────────────────────────────────────┘
```

---

### 9. 보고서 작성 (Reporting) 단계

모의 침투 결과를 기술적/경영적 관점에서 구조화하여 문서화하고, 근본적 개선 대책을 제시합니다.

```
보고서 구조 체계:
┌─────────────────────────────────────────────────────────┐
│  1. 종합 요약 (Executive Summary)                       │
│     - 테스트 배경, 범위 및 종합 보안 위험도 평가          │
├─────────────────────────────────────────────────────────┤
│  2. 기술적 취약점 상세 (Technical Findings)             │
│     - 취약점 설명, CVSS 점수, 실제 공격 경로 재현 절차    │
├─────────────────────────────────────────────────────────┤
│  3. 근본 원인 및 개선 방안 (Root Cause & Remediation)   │
│     - 취약점의 구조적 원인 규명 및 단기/중장기 보호 대책  │
├─────────────────────────────────────────────────────────┤
│  4. 롸잇업 가이드라인 준수                              │
│     - [WRITEUP_GUIDE.md](WRITEUP_GUIDE.md) 필수 체크리스트 검증     │
└─────────────────────────────────────────────────────────┘
```

# 3. 방법론별 도구 매트릭스

| :--- | :--- | :--- | :--- | :--- |
| **포트 스캐닝** | `nmap` | `masscan`, `rustscan` | `nc`, `telnet` | [`item/reconnaissance`](item/reconnaissance/) |

## 2. 취약점 분석 & 초기 침투 (Assessment & Access)

| 카테고리 | 자동화 도구 | 수동 검증 / 인터셉트 | 익스플로잇 기법 | 관련 치트시트 |
| :--- | :--- | :--- | :--- | :--- |
| **웹 애플리케이션** | `nikto`, `wpscan` | `Burp Suite`, `mitmproxy` | 수동 페이로드 인젝션 | [`item/SQLi`](item/SQLi/), [`item/wordpress.md`](item/wordpress.md) |
| **SQL 인젝션** | `sqlmap` | 브라인드 수동 검증 | Union/Time/Error Injection | [`item/sqlmap`](item/sqlmap/) |
| **자격증명 무차별대입** | `hydra`, `medusa` | 커스텀 파이썬 스크립트 | 사전 공격 (`rockyou`) | [`item/cracking`](item/cracking/), [`item/rockyou.md`](item/rockyou.md) |
| **리버스 셸 / 웹셸** | `msfvenom` | 수동 한 줄 셸(One-liner) | PTY 스폰 및 TTY 업그레이드 | [`item/reverse_shell`](item/reverse_shell/), [`item/shell_upgrade`](item/shell_upgrade/) |

## 3. 권한 상승 & 측면 이동 (PrivEsc & Lateral Movement)

| 카테고리 | Linux 도구 / 기법 | Windows 도구 / 기법 | 목적 | 관련 치트시트 |

# 4. 성공적인 침투 테스트의 핵심 원칙

### 1. 체계적 접근법 (Methodological Discipline)
- 각 단계를 건너뛰지 않고 순차적으로 진행합니다.
- 이전 단계(Recon)에서 수집한 정보를 바탕으로 취약점 가설을 수립합니다.
- 재현 가능한 스크립트와 명령어 형태로 결과를 기록합니다.

### 2. 가설 기반의 심층 수동 분석 (Deep-Dive Analysis)
- 자동화 도구의 출력 결과를 무조건 맹신하지 않고 수동 검증으로 False Positive를 제거합니다.
- [롸잇업 작성 가이드](WRITEUP_GUIDE.md)에 따라 **정상 기준(Baseline)과 공격 결과의 응답 차이**를 철저히 대조합니다.

### 3. 환경별 적응 및 안전한 롤백 (Environment & Safety)
- **내부망 / AD 환경**: Kerberos 인증 결함, 신뢰 관계 악용, NTLM 릴레이 고려
- **웹 환경**: OWASP Top 10 기반 논리적 비즈니스 결함 및 인젝션 집중
- **사후 안전**: 침투 과정에서 배포한 모든 바이너리/웹셸을 테스트 종료 후 완벽히 회수
